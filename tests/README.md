# Автоматические проверки

Простые скрипты без фреймворка (решение автора). Каждый `test_*.gd` это сценарий на `SceneTree`: он загружает комнату, «играет» (нажимает действия через `Input`), печатает `PASS`/`FAIL` по каждой проверке, в конце `=== FAILS: N` и выходит с кодом N.

## Запуск

Из корня проекта в PowerShell:

```powershell
.\tests\run_tests.ps1            # все тесты без окна
.\tests\run_tests.ps1 -Window    # плюс тест мыши (окно за пределами экрана, мышь не двигать)
```

Если Windows не даёт запустить `.ps1` (политика выполнения скриптов), запускайте так: `powershell -ExecutionPolicy Bypass -File .\tests\run_tests.ps1`.

Раннер сначала делает импорт проекта, затем запускает каждый тест отдельным процессом Godot и печатает итог. Путь к Godot по умолчанию Steam-сборка автора, другой задаётся параметром `-Godot`. Один тест вручную:

```
godot --headless --path <проект> --fixed-fps 120 --script res://tests/test_shooting.gd
```

`--fixed-fps 120` нужен: один кадр равен одному тику физики, тесты идут быстрее реального времени.

## Правила для тестов

- **Ожидания берутся из ресурсов** (`.tres`, настройки на узлах), а не из запомненных чисел: автор правит числа в Inspector, тесты не должны от этого краснеть. Проверено на копии проекта с сильно изменёнными числами.
- Тесты завязаны на раскладку `rooms/test_room.tscn` (мишени, башни, склон, место старта). Врагов комнаты (узел `Enemies`) тесты убирают и ставят своих в известные места. Если меняете комнату, поправьте координаты в тестах.
- В `--script`-режиме типы, зависящие от автозагрузок (`Player`, `Weapon`, `Enemy*`, `Pickup`, `EnemySpawner`, `ZoneBuilder` и `RoomController` (они ссылаются на `Config`), сами `Config`, `Progress`, `Inventory` и `UserSettings` по имени), недоступны: обращаемся к узлам динамически (`root.get_node("Progress")`), скрипты берём через `load()`, классы врагов сверяем по `get_script().get_global_name()`, зона строим сценой `run/run.tscn`, поэтому в начале файла `@warning_ignore_start("untyped_declaration")`. Общий код без автозагрузок (`NavigationBaker`, `ZoneGenerator`, `RoomInfo`, `RoomCatalog`) называть по имени можно.
- Новый `class_name` виден скриптам только после импорта (`godot --headless --import`, раннер делает его сам).
- Карта навигации подхватывает новый регион не сразу (около 8 кадров), запросы раньше этого возвращают нулевую точку: тесты ждут, пока регион появится (`_wait_navigation`).
- `tests/capsule_walker.gd` (подключается через `preload`) водит по пути навигации тело с капсулой игрока физически. Сетка разрешает ступеньки до 0.3 м, капсула без прыжка берёт около 0.1 м, поэтому ходок прыгает при застревании и считает прыжки.
- Строки `INFO` в выводе ничего не проверяют, это числа для оценки автором (время убийства).
- Лямбда в GDScript захватывает локальные переменные по значению: счётчики держим в `Dictionary`.
- `Input.action_press` из скрипта делает `is_action_just_pressed` истинным на тик позже, чем `is_action_pressed`.
- Захват мыши работает только в окне. Пока идёт `test_mouse_look`, физическую мышь не двигайте.
- Классы, зависящие от автозагрузок и их имена (`Customer`, `HubStation`, `HubScene`, `ShopFloor` и т.п.), в `--script` называть нельзя: значения их `enum` берутся числовыми константами в начале теста (`S_INSPECT`, `K_CHEST` и др. в `test_hub.gd`), звенья через `get_node` и `get_script().get_global_name()`.
- Ошибка скрипта (`SCRIPT ERROR`) посреди `await` молча обрывает тест: сначала смотрите `*.err.txt`/вывод на ошибки, потом на `PASS`/`FAIL`.
- Новая функция: добавляйте проверки в подходящий файл или новый `test_*.gd` (раннер подхватит сам).
