# Процесс разработки и структура проекта

Кратко: как организован проект Godot, кто что делает и в каком порядке строится прототип вертикальными срезами. Назад в [[00-index]].

> [!info] Для Claude Code
> - Язык — GDScript (решение автора).
> - Строй прототип срезами в порядке ниже. Каждый срез играбельный: после него автор запускает игру и проверяет. Не переходи к следующему срезу без согласия автора.
> - Что входит в каждый срез, берёшь из [[10-prototype-scope]]. Чего там нет, не делай.
> - Числа подбираешь ты, значения лежат в Resource ([[09-tech-godot]]).
> - Предложения ниже, помеченные «по умолчанию», автор может изменить.

## Разделение работы

По умолчанию:

| Делает Claude Code                                                                                        | Делает автор в редакторе Godot      |
| --------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| Скрипты, логика, генерация, данные в Resource, простые комнаты-заготовки, раскладка GridMap, точки входов | Более комплексные комнаты-заготовки |
| Сборка простых сцен кодом или минимальными правками `.tscn`                                               |                                     |
| Плейсхолдеры из примитивов Godot                                                                          | Модели, текстуры, финальный арт     |
| Балансные числа в Resource                                                                                | Плейтест и список замечаний         |
| Вёрстка интерфейса (контейнеры, якоря, темы), если правка сцены нужна                                     |                                     |


## Структура папок

Корень проекта `endless-zavod/` (рядом с `project.godot`). Папки по функциям, у каждой сцены скрипт лежит рядом с ней.

```
endless-zavod/
├── project.godot
├── CLAUDE.md
├── .gitignore
├── gameDesign/          диздок (Obsidian)
├── autoload/            глобальные системы: игровые часы, конфиг, события
├── data/
│   ├── definitions/     скрипты классов Resource (часть, производитель, враг, комната, покупатель)
│   └── content/         сами данные .tres
│       ├── parts/
│       ├── manufacturers/
│       ├── enemies/
│       ├── rooms/
│       ├── customers/
│       └── balance/     константы, таблица уязвимостей, шкала качества, пулы названий
├── player/              персонаж, движение, хук, ближний бой
├── weapons/             оружие, стрельба, генерация, сборка модели из частей
├── enemies/             враги, боссы, ИИ
├── generation/          генератор зоны, соединение комнат, пул комнат
├── rooms/               комнаты-заготовки (сцены)
├── run/                 забег: зоны, эвакуация, смерть, потеря лута
├── hub/                 магазин-хаб: прилавки, покупатели, касса, сундук
├── inventory/           инвентарь, предметы, карточка
├── ui/                  HUD, экраны, темы
├── localization/        таблицы переводов (русский)
├── assets/              плейсхолдеры, потом модели, текстуры, звук
└── tests/               тесты логики: простые скрипты без фреймворка, запуск run_tests.ps1
```

Автор может переименовать папки. Новые папки верхнего уровня Claude Code создаёт только по согласованию.

## Срезы прототипа

Общие условия для каждого среза:
- перед началом короткий план и список файлов;
- в конце проверка (раздел «Проверка работы» в `CLAUDE.md`) и описание того, что автору проверить в игре;
- коммит делает автор, Claude Code предлагает его перед следующим срезом;
- в срезе нет функций из соседних срезов, даже если они «почти готовы».

### Срез 0. Каркас

- Проект Godot (версию выбирает автор), структура папок, InputMap (клавиатура и мышь), таблица переводов (русский).
- Autoload: игровые часы, конфиг (включая `pause_in_run`, [[09-tech-godot]]).
- Одна тестовая серая комната.
- Готово, когда: проект запускается без ошибок, комната загружается, действия ввода заведены.

### Срез 1. Персонаж и движение

- Вид от первого лица, ходьба, спринт, приседание, скольжение, двойной прыжок, хук ([[02-combat-fps]]).
- Серая комната с вертикальными площадками для проверки хука.
- Здоровье 100, минимальный HUD (HP, прицел) по [[11-UI-design]].
- Проверяет автор: приятно ли двигаться, плавно ли тянет хук. Числа движения правятся через Resource.

### Срез 2. Стрельба

- Стартовое оружие: вечный пистолет из фиксированного набора частей без аксессуара. Пока без генерации, части заданы данными.
- Магазин, перезарядка, бесконечные патроны, разброс, крит, ближний бой на одну кнопку.
- Прицеливание на ПКМ, стрельба лучом, отдача, автоперезарядка (№65, №66).
- Патроны на HUD (дуга у прицела и счётчик).
- Мишени-болванки с полоской здоровья для отладки.
- Проверяет автор: приятно ли стрелять и бить в ближнем бою.

### Срез 3. Враги и урон

- Четыре типа врагов: преследующий, летающий, турель, саппорт ([[02-combat-fps]]).
- Классы врагов и таблица уязвимостей по типам оружия в Resource. Стихии: кислота, электричество, мороз, огонь как заглушка.
- Смерть врагов, дроп (деньги, аптечки), опыт и уровень персонажа, цифры урона. Смерть игрока: экран и перезапуск по клавише (№68).
- Время убийства рядового врага 0,3-1,0 с.
- Проверяет автор: чувствуется ли разница между типами врагов, время убийства.

### Срез 4. Составное оружие

- Данные частей, вариантов, производителей (5, №70), шкала качества, уровень оружия ([[02-combat-fps]]).
- Генератор оружия: независимый выбор производителя каждой части, совместимость по типу, модификаторы по качеству, аксессуар с особенностью, название (база, модификаторы названия, префиксы).
- Сборка модели оружия из частей (плейсхолдеры), 8 типов оружия (№72), 4 слота.
- Отладочная выдача случайного оружия.
- Тесты на логику генерации, если автор выберет фреймворк.
- Проверяет автор: чувствуется ли разница между сборками, разумны ли названия.

### Срез 5. Инвентарь и карточка

- Инвентарь 20 предметов, экран, экипировка, ограничение по уровню, сортировка и фильтр ([[11-UI-design]], [[05-shop-economy]]).
- Всплывающая карточка оружия, сравнение, режим «Компоненты», карточка прочих предметов.
- Панель слотов оружия на HUD, пауза при открытом инвентаре.
- Проверяет автор: удобно ли пользоваться, читается ли карточка.

### Срез 6. Генерация зоны

- Комнаты-заготовки со списком входов, генератор в трёх измерениях, коридоры и переходы ([[03-run-structure]], [[09-tech-godot]]).
- Типы комнат: стартовая, с врагами (дверь закрывается), кладовая, магазин, босс, эвакуационная. Несколько вариантов каждого, число комнат растёт с зоной.
- Уровень зоны по формуле, фиксированный сид для отладки.
- Тут автору нужно подготовить комнаты в редакторе. Claude Code сначала даёт минимальный набор простых тестовых комнат, чтобы проверить генератор.
- Проверяет автор: не ломается ли генерация, интересна ли структура зоны.

### Срез 7. Забег целиком

- Отдел из 10 зон (число зон параметр), смена зон через шлюз (волны врагов или элитный враг, затем портал), босс отдела ([[04-extraction]], №82).
- Комната эвакуации (оплата деньгами или лутом, либо 3 волны), смерть с потерей лута, вечные предметы, уровень мира после босса, экран итогов забега (хаба ещё нет).
- Деньги в забеге, магазин-комната с оружием и аптечками.
- Проверяет автор: есть ли напряжение «идти глубже или выходить».

### Срез 8. Хаб-магазин

- Магазин как хаб ([[05-shop-economy]]): прилавки, сундук, справочник цен, назначение цены.
- Покупатели с предпочтениями, бюджетом и модификатором нежелания, шанс покупки, касса.
- Сутки 20 минут (12 день и 8 ночь), торговля ночью менее выгодна.
- Вход в забег из магазина.
- Минимальный расход денег ([[10-prototype-scope]], вопрос о торговце ждёт подтверждения автора).
- Проверяет автор: интересно ли торговать, чувствуется ли разница между днём и ночью.

### Срез 9. Замкнутая петля и проход по балансу

- Сквозной сценарий: магазин, забег, лут, выход или смерть, возвращение, продажа, трата, новый забег.
- Отладочные инструменты (выдать оружие и деньги, переключить время суток, задать уровень мира, зафиксировать сид).
- Список числовых правок по плейтесту автора.
- Готово, когда выполняется условие из [[10-prototype-scope]] («Готовность прототипа»).

## Журнал состояния

В корне диздока ведётся [[progress]]: сжатое итоговое состояние проекта (что реализовано и где лежит, что в работе, какие допущения приняты, что не проверено). Это не лог шагов: Claude Code правит существующие пункты по мере работы и удаляет устаревшее, чтобы новая сессия за один файл получала полный контекст и не тратила его на историю. Каждая новая сессия начинается с этого файла.
